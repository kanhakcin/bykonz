# i18n — Detalhamento

Este documento expande a Regra 1 da `iotlog-standards`. As **5 regras inegociaveis** estao na SKILL.md; aqui voce encontra o porque, o protocolo de busca, e a tabela errado vs certo.

## Por que reuso de chaves importa

O projeto tem milhares de chaves espalhadas por `pt.json`, `en.json` e `es.json`. Cada chave nova criada por inercia gera tres custos reais:

1. **Inflacao do bundle.** Tres locales = tres copias. Chaves verbosas multiplicam o tamanho da traducao carregada pelo navegador.
2. **Fragmentacao do vocabulario.** "Salvar" ja existe como `save`. Criar `feature.x.button.save.label` significa que a UI agora tem dois conceitos de "salvar" — e eles podem divergir entre locales.
3. **Risco de chave fantasma.** Cada locale extra que voce esquece de preencher vira fallback silencioso para a chave crua na tela.

O grep custa 2 segundos. Reescrever traducoes depois custa horas. **Buscar antes de criar e parte do trabalho, nao etapa opcional.**

---

## Protocolo de busca em camadas

Antes de adicionar **qualquer** chave nova, busque do mais especifico para o mais amplo. Pare quando achar algo equivalente.

### Camada 1 — conceito exato (verbete em PT)

```bash
grep -nE '"construir"|"construtor"|"construa"' src/lib/config/translations/pt.json
```

Casos em que voce nao vai achar: termos de marketing ("Construa paginas no estilo Lovable"). Termos isolados quase sempre existem ("Construtor de paginas" → tente `builder`, `construtor`).

### Camada 2 — dominio existente

```bash
# Prefixos relacionados ao seu contexto
grep -nE '^\s*"(ai|page|builder|dashboard)\.' src/lib/config/translations/pt.json
```

Util quando o conceito ja foi traduzido sob outro dominio. Ex: `ai.assistant` ja existe, nao crie `chat.ai.assistant.title`.

### Camada 3 — acoes/labels genericos

```bash
grep -niE '"(save|cancel|create|edit|delete|new|generate|build|description|title|name|code)"' src/lib/config/translations/pt.json
```

A maioria das acoes globais ja existe sem prefixo. Reuse-as cruas.

### Quando criar

Apenas se as tres camadas vierem vazias **e** o conceito for genuinamente novo. Pequenas variacoes de redacao **nao** justificam chave nova — uniformizar o vocabulario e o objetivo.

---

## Como nomear quando criar mesmo

Chaves novas precisam ser **curtas, baseadas em conceito, e reaproveitaveis** em outras telas. Nunca ancore no caminho da rota ou na posicao do elemento.

| Principio                                            | Errado (verboso, page-locked)                                  | Certo (curto, reaproveitavel)             |
| ---------------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------- |
| Conceito, nao posicao na UI                          | `ai.page.builder.intro.title`                                  | `page.builder` ou `build.pages`           |
| Acoes globais ja existem — nao prefixe com a feature | `ai.page.builder.button.new.label`                             | `new.page` (ou apenas `new`)              |
| 2-3 segmentos sao quase sempre suficientes           | `dashboard.machine.consumption.title.label`                    | `machine.consumption`                     |
| Valor curto, nao frase de marketing                  | `"Construa paginas estilo Lovable arrastando e soltando"`      | `"Construtor de paginas"`                 |

**Regra pratica:** se a chave tem 4+ segmentos e e exclusiva de uma unica tela, voce esta sobreescrevendo. Recue uma camada — provavelmente existe um conceito mais curto que cabe ali ou ja serve a varias telas.

## Chaves comuns reutilizaveis

A maioria do que voce vai querer escrever ja esta aqui. **Cheque antes de criar variantes prefixadas.**

| Categoria   | Chaves                                                                                       |
| ----------- | -------------------------------------------------------------------------------------------- |
| Acoes       | `save`, `cancel`, `delete`, `edit`, `add`, `create`, `new`, `update`, `confirm`, `close`, `generate` |
| Estados     | `loading`, `error`, `success`, `empty`, `active`, `inactive`                                 |
| Labels      | `name`, `description`, `code`, `date`, `status`, `actions`                                   |
| Composicoes | `general.information`, `advanced.settings`                                                   |

Se uma dessas resolve sua tela, **use crua** — nao crie `feature.x.save` so para nao "poluir" o espaco global. O espaco global existe exatamente para isso.

---

## Separador de chaves — apenas `.`

Use **somente `.`**. Nunca `-`, `_` ou outros caracteres de rota.

O `PageBreadcrumb` (e outros processos que derivam chaves a partir da URL) converte `-` em `.` antes de buscar a traducao. Se voce salvar `"distance-more-than"` no JSON, o breadcrumb procura por `distance.more.than` e **nao encontra** — falha silenciosa, sem erro de build.

```
# CORRETO
"distance.more.than": "Distance greater than (nm)"
"service.order": "Service Order"

# PROIBIDO — quebra breadcrumb/card sem aviso
"distance-more-than": "..."
"service_order": "..."
```

---

## Adicionar nos 3 locales

Se voce **realmente** precisa de chave nova, adicione em `pt.json`, `en.json` e `es.json` na mesma edicao. Nunca deixe os outros locales "para depois" — vira chave fantasma.

```bash
# Confira que existe nos 3
grep -nl '"sua.chave.nova"' src/lib/config/translations/*.json
# Deve listar os 3 arquivos
```

---

## Uso no codigo

```tsx
const { t } = useTranslation();

<ItemTitle>{t('page.title')}</ItemTitle>
<ItemDescription>{t('welcome.message', { name: 'User' })}</ItemDescription>
<Input placeholder={t('search.placeholder')} />
```

Sem excecoes para strings visiveis: titulos, labels, placeholders, mensagens de erro, tooltips, toasts — **tudo** passa por `t()`.

## Ferramentas auxiliares

Scripts em `src/lib/config/translations/` ajudam na manutencao:

| Script                | Proposito                                              |
| --------------------- | ------------------------------------------------------ |
| `i18n_check_missing.py` | Lista chaves usadas no codigo que faltam no JSON     |
| `i18n_validate.py`    | Confere paridade entre os 3 locales                    |
| `i18n_deduplicate.py` | Identifica chaves duplicadas/semanticamente iguais     |
| `i18n_remove_unused.py` | Remove chaves que ninguem usa mais                   |
| `i18n_sort.py`        | Ordena alfabeticamente os 3 arquivos                   |

Rode `pnpm run i18n:check` antes de abrir PR.
